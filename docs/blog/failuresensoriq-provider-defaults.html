Testing AI answers about machine faults at provider defaults

Siddharth Srinivasan · October 2026 · IMC-EXP-012

When I ask an AI model which sensor could detect a machine fault, what should count as a correct answer? I ran four models on IBM’s FailureSensorIQ questions using their provider defaults. The results made response behavior an important part of interpreting the scores.

Keeping the questions and scoring fixed

I used the original single-answer split of FailureSensorIQ: 2,667 questions, each with one released correct answer among two to five options. The comparison covered Gemini 3.8 Flash, Gemini 3.1 Pro preview, Gemini 4 Argon and GPT-6.1 Sol. I reused IBM’s original prompt, its “Let’s think Step by Step” trigger, and its answer parser. The system instruction was the same generic helpful-assistant instruction for every model; the correct answer never entered the prompt.

I left generation controls unspecified, so each provider applied its defaults. That is an intentional difference from IBM’s reference runner, which sets temperature to zero. This experiment therefore tests these models under provider defaults, rather than reproducing IBM’s published model results.

The scoring rule was exact agreement with the released answer key. The parser turns a model’s answer into a record of which options it selected. A response scores one point only if that complete selection matches the key; any other selection scores zero. Selecting the correct option along with another option still scores zero.

A larger run was interrupted by Gemini Pro’s daily request quota. I closed collection at 702 completed model evaluations: 178 for Flash, 170 for Pro, and 177 each for Argon and Sol. Those are model evaluations, not 702 different questions. The intended 512-question panel and full benchmark were not completed.

To compare like with like, I used the 170 question IDs that all four models completed. That gives 680 matched evaluations; the other 22 responses remain in the supporting records as secondary observations. The shared questions are the first 170 in the dataset’s original order, covering electric motors, steam turbines, aero gas turbines and industrial gas turbines. All ask about sensors relevant to failure modes. This is an exploratory convenience subset, not a representative sample of the full benchmark.

Pro had the highest count, but its lead over Flash was just one question, or 0.59 percentage points. On their matched questions, Pro was correct when Flash was wrong eight times, while Flash was correct when Pro was wrong seven times. This does not establish a clear general winner between them.

The paired analysis also resampled the four equipment classes to examine how sensitive the differences were to their composition. For Flash minus Pro, that descriptive 95% range was −7.25 to +6.78 percentage points. With only four classes, dataset-order selection and related question templates, these ranges are sensitivity descriptions rather than reliable population confidence intervals. They do not establish statistical equivalence or confirmatory superiority.

Sol and Argon had lower exact-answer accuracy on this subset. That observation needs to be read alongside what the models actually selected.

Multiple answers changed what the score meant

Argon selected multiple options on 63 of the 170 shared questions. Sol did so on 33, compared with eight for Pro and six for Flash. Those selections cannot exactly match a key that contains one correct option, so they all score zero under the fixed rule.

There is a protocol limitation here: IBM’s original prompt asks for the correct “option(s)” and an answer list. I preserved that wording, even though the selected split has one correct answer per question. The score therefore combines exact selection against the benchmark key with how a model interprets and responds to that interface. A lower score is not, by itself, evidence that a model has less industrial knowledge.

The distinction also matters for empty answers. Argon and Sol each produced one zero-selection answer, and Pro produced two. These are parser outcomes, not independent demonstrations that a model did not know. There were no exhausted answer-format failures among the completed evaluations.

I have kept the strict metric unchanged. Giving partial credit after seeing the responses would answer a different question and change the interpretation of this experiment. The public records retain every prediction and answer key so that the limits of the original score remain inspectable.

What was preserved, and what remains untested

The completed responses came from 719 recorded HTTP attempts: 702 successful responses, eight recovered Sol timeouts, eight unscored Pro quota responses, and one earlier truncated Pro request. The truncated response body is unavailable and its possible billing remains unknown; that logical question has a separately preserved completed response. Operational errors never counted as wrong answers.

Recorded successful token usage corresponds to approximately $4.16 at the preserved list prices. This is not an invoice or a remaining account balance; uncertain failed-request charges and review usage are separate. Provider defaults can also change between execution sessions, so the requested and returned model identities, output text, usage and execution records were retained.

The result package passed an independent, read-only Claude Opus 5 review, which replayed the answers and reproduced the counts, paired statistics and costs. That was model-assisted methodological verification, not academic peer review. The public package contains the response texts and an offline reproduction script; provider account details and private review conversations are excluded.

This was one pass on a small, selected part of the dataset. It did not measure repeated-run consistency, independently adjudicated hallucinations or reasoning quality, performance against humans, elimination questions, or behavior in an operating plant. Unknown training exposure and dependence among question templates further limit broader conclusions.

Conclusion

Under provider defaults and IBM’s strict answer-key scoring, Pro and Flash had similar observed accuracy on these 170 questions, separated by one correct answer. Sol and Argon scored lower, but multiple selections materially affected that ordering. The experiment does not isolate industrial reasoning ability or establish a general model ranking.

A specific next question is whether that response pattern persists in a prospectively designed comparison that explicitly requests one answer and measures both correct selections and extra incorrect selections. That would be a separate experiment with a new prompt protocol, rather than a correction to these frozen results.
