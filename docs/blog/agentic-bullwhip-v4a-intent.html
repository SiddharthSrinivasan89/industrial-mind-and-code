Correctly formatted labels, wider order swings

Siddharth Srinivasan · April 2026

Would choosing a label work better than asking AI to choose a numerical setting? I gave gpt-4.1-mini five possible answers and let software turn each answer into an order. Every response used a valid label, but the resulting order variability remained far above a simple smoothing rule.

Five labels, with the calculation left to code

At each month and supply-chain tier, gpt-4.1-mini chose a label from strong decrease through neutral to strong increase. A fixed lookup converted the label into a buffer multiplier. An Order-Up-To formula then calculated the actual order.

The model supplied neither an order quantity nor a numerical multiplier. This made it possible to ask two separate questions: could it reliably use the interface, and would its choices produce effective inventory control?

Testing format and performance separately

The fictional chain consisted of a vehicle manufacturer, an ancillary supplier, and a component maker. It served one product over 25 months of synthetic demand representing Indian automotive seasonality. Lead times were fixed at one month, with no injected disruptions or demand shocks.

The model received numbers alone, numbers with calendar context, or a stateful version with recent history. Each condition ran twenty times. Exponential smoothing and a fixed-buffer version of the ordering formula provided deterministic baselines.

I tracked label compliance, stockouts, and chain OVAR. OVAR averages each tier's ratio of order variance to demand variance: below one means damping; above one means amplification. Compliance answers a narrower question—whether software can accept the response—not whether the response leads to a good order.

Compliance was 1.000 throughout, and no fallback responses were needed. Yet the model conditions produced roughly six to seven times the OVAR of exponential smoothing, which also recorded fewer stockouts.

Calendar context reduced OVAR relative to numbers alone, but did not close the gap to either baseline. Restricting the answer format made the responses usable by software without making their operational consequences effective. Those are different achievements.

Checking the result with more repetitions

The experiment started with ten repetitions per condition and expanded to twenty. The headline means changed by less than one standard deviation. The twenty-run set is the result of record; stability across those repetitions is not evidence of generalisation to different demand profiles.

Where the result stops

Only one model, one synthetic demand series, and one simplified chain were tested. The lookup values came from domain logic and were not established as optimal. The result concerns this label-to-multiplier interface, not classification-based control in general.

This intermediate V4a variant led to V4b, which tested the label architecture with disruptions and stochastic supply conditions. That is a different environment. Its results need to be read separately, not merged with this comparison.

Conclusion

The five-label interface achieved complete observed format compliance without effective control relative to the smoothing baseline. Valid responses still produced substantially more variable orders and more stockouts than smoothing. This separates interface reliability from operational quality in the tested setup; it is not a verdict on every classification-based controller or a guarantee of future format compliance.
