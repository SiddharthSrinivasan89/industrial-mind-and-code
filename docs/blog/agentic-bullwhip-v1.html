Does context help AI place supply chain orders?

Siddharth Srinivasan · February 2026

Does giving an AI ordering agent more business context make a supply chain steadier? In this exploratory comparison, context helped gpt-4.1-mini and hurt o1. All four configurations amplified order variability.

The question and the models

The bullwhip effect is the amplification of demand fluctuations as orders move through a supply chain. I tested whether adding company, product, market, and calendar information would help a language model choose orders that reduced that amplification.

The comparison crossed two models—gpt-4.1-mini and o1—with two information conditions. Blind agents received the numerical inventory state. Context agents received the same numbers plus the fictional business identity and calendar information. Each agent was stateless, meaning it had no memory of its earlier decisions.

The data and method

The simulation contained a fictional vehicle manufacturer, a lighting supplier, and a component supplier. All tiers had fixed one-month lead times and started with 43,000 units of inventory. Every run used the same 13-month synthetic demand series, from December 2024 to December 2025, with twelve active ordering periods.

The primary measure was chain OVAR: the average across tiers of order variance divided by the variance of demand received. Below one means damping; above one means amplification. I also examined stockouts and excess inventory, since avoiding shortages by holding much more stock is a trade-off, not a free improvement.

The original design called for five runs per configuration. One stored run in each lightweight condition was recorded with a different model, so the published gpt-4.1-mini comparison excludes those runs and uses four per condition. The o1 comparison uses five. This exclusion is important because older aggregate files still describe the original five-run lightweight set.

Context reduced the lightweight model's chain OVAR by about 7.5%. For o1, it increased OVAR by 0.577, leaving the context condition with the largest mean amplification. The o1 results also varied substantially between runs, so their means are directional rather than precise estimates of expected operational performance.

The o1 context condition had fewer stockouts but substantially more excess inventory. Its mean chain stockout count was 12.8 and its excess-inventory measure was 654,728 units. This is why variance, service, and inventory need to be read together: a model can appear more cautious while making the system more costly or volatile.

The later replication

In July 2026, I reran both lightweight conditions with five runs each on one pinned model version, gpt-4.1-mini-2025-04-14. The recorded chain OVAR was 3.088 ± 0.091 blind and 2.794 ± 0.080 with context, where ± is the standard deviation across runs. That is a 9.5% reduction, in the same direction as the original comparison.

The original batch remains the four-condition comparison. The later run checks the lightweight arm; it does not replace the original o1 comparison or create a simultaneous comparison between model versions.

Limits and next steps

This was a small exploratory study with no deterministic ordering baseline, one demand series, one product, and one simplified topology. Order limits constrained extreme outputs. It cannot establish whether context generally helps, whether reasoning models generally hurt, or whether a different memory design would change the result. The hypotheses were not pre-registered.

The next experiment added simple deterministic baselines and more repetitions. That changes the question from which model configuration looks best to whether any model improves on a straightforward ordering rule.
