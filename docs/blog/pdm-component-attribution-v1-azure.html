Finding out which part broke

Siddharth Srinivasan · July 2026

A machine has broken down. Can a language model use the preceding evidence to identify which component failed? I compared three models with simpler methods on a simulated maintenance dataset. Historical statistics helped the language models, but the trained classifier led the comparison.

Identifying a failed component—not predicting a breakdown

Each model was told that a failure had occurred and asked to choose which of four components had failed. This was component attribution. It was not a test of detecting a failure, predicting a future breakdown, or establishing its physical cause.

The models were gpt-5.4, gpt-oss:120b, and nemotron-3-super:120b. Nemotron joined the primary comparison after its results were visible. That is a documented post-hoc addition, not an independently planned confirmation; the original two-model conclusions do not depend on it.

The evidence available to each method

Microsoft's Azure Predictive Maintenance sample simulates 100 machines over 2015. It records hourly voltage, rotation, pressure, and vibration, along with error codes, component replacements, and failures. Selecting single-component failures yielded 677 events across 98 machines. A chronological split used 464 earlier events for training and 213 later events for evaluation. The test concerns later events in the same fleet, not transfer to unseen machines.

For each evaluation event, the models received a text summary drawn strictly from before the failure: machine characteristics, three days of telemetry, a week of errors, and time since each component's replacement. The zero-shot condition used that evidence alone. The with-history condition added a frozen summary of training-period failure rates and error frequencies.

Five baselines provided reference points: prior-weighted random guessing, majority guessing, selecting the oldest component, mapping the most recent error to a component, and a trained logistic-regression classifier. The simulator's recorded labels supplied the answers; no language-model judge was used.

The primary measure was macro-F1, which gives each component equal weight. I also recorded accuracy. Confidence intervals came from resampling machines, keeping failures from the same machine grouped together.

The trained classifier scored 0.995 [0.983, 1.000]. The recent-error rule scored 0.923 [0.881, 0.959], and the oldest-component heuristic scored 0.467 [0.395, 0.534]. Training-period statistics substantially improved all three language models, but none exceeded the recent-error rule's point estimate.

A higher point estimate does not settle every comparison. The recent-error rule's interval overlaps those of the with-history models, and no formal paired superiority or equivalence test compared them. The classifier's interval, in contrast, did not overlap any language-model interval.

Logistic regression was the frozen champion baseline. An exploratory gradient-boosting alternative scored 1.000 on the same evaluation, but it was not the preselected baseline. Its result does not replace the frozen comparison.

A separate check on component names

A 51-event probe renamed components and error codes. The paired accuracy gaps were zero for gpt-5.4, +0.059 for gpt-oss:120b, and −0.039 for Nemotron; positive gaps mean accuracy fell after renaming. This was a small descriptive probe, not proof of label invariance or absence of contamination. The prescribed observed-data minimum-detectable-effect calculation was not run, a disclosed protocol deviation.

What this says about the task

In this simulator, trained methods could use the relationship between error codes and failures. Giving the language models historical statistics closed much of their initial gap. That supports the value of the statistics in these runs; it does not isolate reasoning ability. Nor was the information identical across approaches: the classifier learned from labeled examples, while the models received a summary.

The findings concern simulated, same-fleet component attribution using this evidence representation. They do not establish real-factory diagnostic capability or autonomous maintenance safety. The hypotheses were stated before analysis but were not formally pre-registered.

The next question is whether the comparison holds beyond this simulator and fleet. Answering it would require further work, retaining simple baselines and keeping component identification distinct from failure prediction.
