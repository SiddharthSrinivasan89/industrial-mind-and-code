Finding out which part broke

Siddharth Srinivasan · July 2026

When a machine has already broken down, can a language model identify the failed component from the evidence that came before it? I compared three models with simpler methods on a simulated maintenance dataset.

The question and the models

This experiment tested component attribution: choosing which of four components failed. It did not test whether a breakdown could be predicted, whether a failure could be detected, or what physically caused it. Each model was told that a failure had occurred.

I tested gpt-5.4, gpt-oss:120b, and nemotron-3-super:120b. Nemotron was added to the primary comparison after its results were visible, so it is a documented post-hoc addition rather than an independently planned confirmation. The original two-model conclusions do not depend on including it.

The data and method

Microsoft's Azure Predictive Maintenance sample simulates 100 machines over 2015. It includes hourly voltage, rotation, pressure, and vibration readings, alongside error codes, component replacements, and failure records. After selecting single-component failures, there were 677 events across 98 machines. A chronological split assigned 464 earlier events to training and 213 later events to evaluation. This tests later events in the same fleet, not transfer to unseen machines.

For each evaluation event, the input was a text summary of evidence strictly before the failure: machine characteristics, three days of telemetry, a week of error records, and time since each component's replacement. The zero-shot condition supplied this evidence alone. The with-history condition added a frozen summary of training-period failure rates and error frequencies.

Five baselines were included: prior-weighted random guessing, majority guessing, selecting the oldest component, a rule mapping the most recent error to a component, and a trained logistic-regression classifier. Predictions were checked against the simulator's recorded labels, without a language-model judge. The main measure was macro-F1, which gives each component equal weight; accuracy was also recorded. Confidence intervals were calculated by resampling machines, preserving the grouping of failures from the same machine.

The trained classifier scored 0.995 [0.983, 1.000]. The recent-error rule scored 0.923 [0.881, 0.959], and the oldest-component heuristic scored 0.467 [0.395, 0.534]. All three language models improved substantially with training-period statistics, but none exceeded the recent-error rule's point estimate.

That last comparison needs care. The rule's interval overlaps those of the with-history models, and neither a formal paired superiority test nor an equivalence test compared them. A higher observed score is not proof of a statistically established advantage. The classifier's interval, by contrast, did not overlap any language-model interval. Logistic regression was the frozen champion; an exploratory gradient-boosting alternative scored 1.000 on the same evaluation but was not the preselected baseline.

A separate 51-event probe renamed components and error codes. The paired accuracy gaps were zero for gpt-5.4, +0.059 for gpt-oss:120b, and −0.039 for Nemotron, with positive gaps indicating a drop after renaming. This small, descriptive probe cannot establish absence of contamination or invariance to labels. The prescribed observed-data minimum-detectable-effect calculation was not run, a disclosed protocol deviation.

What the result means

On this simulator, the trained methods could exploit the relationship between error codes and failures. Supplying historical statistics closed much of the language models' initial gap. This supports the value of those statistics in these runs; it does not isolate reasoning ability. The classifier also learned from labeled examples rather than just a summary, so the information available to the approaches was not identical.

These are results for simulated, same-fleet component attribution using this evidence representation. They are not evidence of real-factory diagnostic capability or autonomous maintenance safety. The hypotheses were stated before analysis but were not formally pre-registered.

Next steps

The open question is whether this comparison holds beyond the simulator and the same fleet. That is a follow-up question, not a result of this study. Any extension would need to retain the simple baselines and distinguish component identification from failure prediction.
